# DDS-first MVP после Q&A

## Context
Письменное ТЗ содержит два потока, но Q&A заказчика17:42–18:51,21:41–24:11,39:12–39:59 прямо ставит готовую карточку ДДС и исходящий звонок должностному лицу в центр первого прототипа. На рынке есть voice-first аналоги. Нет утверждённой рубрики и данных педагогического пилота.

## Decision
Создать единый полный workflow ДДС с faithful ARM, программным учебным телефоном, утверждаемыми сценариями, журналом и доказательным разбором. Тайминг реакции30с и обработки180с — отдельные изменяемые учебные параметры. Правила проверяют структурные события; смысловая модель помогает с текстом, спорное проверяет преподаватель. React+FastAPI, SQLite для простого локального запуска, PostgreSQL через конфигурацию.

## Alternatives
Voice-first симулятор гражданина исключён заказчиком для первой версии. Два MVP отвлекают от основного пути. Только квиз не обучает работе в АРМ. Единый LLM-score непроверяем и не учитывает действия. Облачные обязательные API не соответствуют локальному контуру.

## Consequences
Нужно воспроизвести терминологию и расположение элементов АРМ. Первичную карточку112 сохраняем в coverage backlog как расхождение письменного ТЗ и Q&A. Не выдаём шаблоны за нейросеть, симуляцию за SIP, технический тест за педагогический эффект. Независимый adversarial benchmark создаётся до реализации.
