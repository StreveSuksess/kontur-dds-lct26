# Первый статус с текстом как трёхминутный рубеж

## Context

Прямой ответ заказчика в Telegram Q&A, сообщение №781 от 27.09.2026, разделяет 30 секунд до открытия поступившей карточки, 3 минуты до первой записи статуса и текста, а также последующие статусы, которые могут занимать часы или дни. До этого учебная рубрика ошибочно сравнивала с трёхминутным лимитом сдачу всей попытки.

## Decision

Сохраняем существующее поле версии сценария `completion_limit_seconds` для совместимости старых снимков, но трактуем его как лимит первого серверно сохранённого `status_changed` с непустым комментарием. Отдельно показываем полную длительность попытки как наблюдаемую величину без этого лимита. Сервер отклоняет новые статусы без текста. Исторический ID критерия `duration` оставлен для сохранения ссылок на старые решения, название для новых попыток обновлено.

## Alternatives

Оставить лимит полного завершения — противоречит сообщению №781. Переименовать поле/ID миграцией — требует преобразования ранее сохранённых снимков и решений в условиях короткого срока. Считать черновик первой записью — он не является сохранённым изменением статуса.

## Consequences

Новые попытки оцениваются по первому статусу с текстом; старые отчёты не пересчитываются задним числом. Смешанные аналитические серии могут содержать старое и новое название критерия при одном ID, поэтому агрегирование и UI используют пару ID+название. Начальная точка в текущем MVP — начало учебной попытки, а не независимое поступление нескольких карточек в очередь; это остаётся известным ограничением.
