# Архитектура текущего прототипа

Состояние: 19 сентября 2026. Этот документ описывает реализованный контур; соответствие требованиям и границы испытаний — в [coverage.md](coverage.md).

## Поток данных

Браузер React → same-origin `/api` → FastAPI → SQLAlchemy → SQLite WAL. В production FastAPI также отдаёт собранный `frontend/dist`; при разработке Vite проксирует `/api` на `127.0.0.1:8000`. CSS, иконки, справочники и звук находятся локально, без CDN. Браузер не обращается к реальным службам или облачному AI.

Преподаватель создаёт черновик, проверяет карточку и рубрику, утверждает версию. Назначение копирует её в неизменяемый снимок попытки. Учащийся получает только публичные поля, начинает попытку, открывает карточку и отправляет события. Сервер проверяет пользователя, состояние попытки и полезную нагрузку, фиксирует серверное время и возвращает сохранённый результат. Отправка работы строит отчёт по снимку и журналу. Проверка преподавателя сохраняет отдельную коррекцию и причину; исходный отчёт не подменяется.

## Хранение и согласованность

Таблицы: `users`, `auth_sessions`, `scenarios`, `training_sessions`, `events`, `audit`. В `training_sessions` находятся снимок сценария, черновик и отчёт. Каждое событие имеет `client_event_id`, вид, время, порядковый номер и payload. Уникальность `(session_id, client_event_id)` обеспечивает идемпотентность повторов; несовместимое повторное использование идентификатора отклоняется. Повтор не создаёт второй звонок или ответ собеседника.

Браузерные ключи черновика и очереди включают пользователя и попытку. Очередь доставляет события последовательно и сохраняется до подтверждения. Перед сдачей требуется её опустошить. `connection_restored` помечает период недоступности; оценщик направляет тайминг на ручную проверку. Серверное время доставки не объявляется точным временем действия при разрыве. localStorage зависит от сохранности профиля браузера; очистка данных браузера, private mode и отказ диска требуют отдельной проверки.

SQLite использует foreign keys, WAL и busy timeout. Процесс имеет блокировку изменений; ASGI AdmissionMiddleware ограничивает число одновременно обслуживаемых API-запросов до **24**, удерживая разрешение до завершения ответа и cleanup зависимостей. Это ограничение нагрузки на синхронный SQLAlchemy/threadpool, не число учащихся. Текущий поддерживаемый запуск — **один Uvicorn worker**. Несколько процессов требуют отдельного анализа блокировок, БД, лимитов и тестов.

`DATABASE_URL` допускает PostgreSQL через psycopg. Совместимость схемы предусмотрена кодом, но PostgreSQL, миграции существующих версий и горизонтальное масштабирование здесь не испытаны. `create_all` создаёт свежую схему, а не выполняет полноценные миграции.

## Оценка и доверие

Время открытия отсчитывается до первого `card_opened`, длительность обработки — до сдачи; это разные критерии. Значения 30 и 180 секунд — настраиваемые учебные параметры, а не срок реального выезда или завершения работ.

Оценщик сравнивает действия с последовательностью именно утверждённого упражнения. Содержательный текст не заменяет событие статуса; ответ учебного контакта не считается собственным докладом учащегося. Небольшой словарь различает подтверждение направления, отрицание, вопрос, будущее и часть неоднозначных формулировок. Общего понимания произвольного русского доклада он не гарантирует. Орфографические замечания не снимают баллы за верный факт. `review` означает отсутствие автоматического подтверждения и необходимость преподавателя.

LLM не вызывается для выставления итоговой оценки. Генератор ограничен формулировками `title`, `card_description`, `contact_reply`, проверяет сохранение заданных фактов и всегда создаёт черновик. Ошибка сервиса/схемы даёт явно обозначенный шаблонный fallback. AI-советы преподавателю принимаются только с существующим ID критерия и дословной цитатой собственного текста учащегося; они не меняют балл. Это проверка опоры на данные, а не доказательство истинности интерпретации модели.

## Локальные сервисы голоса и модели

| Сервис | Loopback | Назначение и ограничения |
|---|---|---|
| llama-server / Qwen3 1.7B Q4_K_M | `11434` | Черновик и советы; CPU, 4 потока, 1 слот; проверен на Mac arm64/48 ГБ |
| Whisper small | `11435` | Raw аудио → проверяемый текст; один слот; 10 МиБ, до 120 с |
| macOS `say` / Milena | `11436` | Полный текст сохранённой реплики → WAV; 1999 символов, один слот, 20 с; только macOS |

Учащийся явно включает запись, получает текст, проверяет его и отдельно отправляет обычное событие. Прокси не сохраняет raw аудио или неподтверждённую расшифровку в БД. TTS endpoint приложения берёт текст из принадлежащего попытке `contact_message`; произвольный текст для озвучки браузер не задаёт. Прямые сервисы доступны только на loopback и не заменяют пользовательскую авторизацию основного API.

Нет реального SIP, подключения РТУ или вызовов на внешние номера. Текстовый режим остаётся доступным при недоступности голосовых сервисов. Docker по умолчанию содержит только основной API/интерфейс с правилами и текстовым телефоном; модели и macOS-runtime в образ не копируются. [Локальный AI](local-ai.md), [TTS](local-tts.md).

## Доступ и эксплуатация

Пароли хешируются scrypt; cookie HttpOnly, SameSite, настраиваемый Secure. Сервер проверяет роль и владельца, блокированного пользователя, скрывает эталон до завершения, ограничивает вход и размеры тела. Для изменяющих запросов проверяются Origin и Sec-Fetch-Site. CSV экранирует формульные значения. Это реализованные меры и регрессионные проверки, не внешний security-аудит.

Деморежим создаёт известные учебные пароли. При отключении demo сервер не продолжит молча использовать их в прежней БД. Новая production-БД и уникальный bootstrap-пароль — отдельная конфигурация. Встроенного TLS, шифрования БД, ротации копий, централизованного мониторинга и автоматического обновления нет.

SQLite backup API создаёт согласованную копию с WAL. Restore принимает только соответствующую схему, проверяет целостность, очищает auth-сессии и публикует новый файл без перезаписи. Данные классификатора, исходные документы, конфигурация и модели вне БД сохраняются отдельно. [Процедура](backup-restore.md).

Dockerfile собирает frontend Node 22 и backend Python 3.12 по lock-файлам, копирует их в runtime, запускает uid 10001 с одним worker. Compose хранит `/app/backend/var` в отдельном volume, основной filesystem read-only, опубликованный адрес по умолчанию `127.0.0.1`. Конфигурация прошла `docker compose config`; build/run не проводились из-за отсутствующего Docker daemon.
