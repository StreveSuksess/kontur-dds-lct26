# Восстановление клиентских действий: проверка 19.09.2026

Проверены конкретные стыки очереди, перезагрузки/возврата в АРМ, телефонного состояния и остановки попытки. Серверная проверка владельца остаётся обязательной: идентификатор пользователя в localStorage сам по себе не даёт доступ к попытке.

## Формат очереди и границы

Ключ события: `kontur:events:<user_id>:<session_id>:event:<client_event_id>`. Значение содержит событие, время постановки и счётчик порядка. Сортировка: `queued_at`, затем `insertion_order`, затем UUID как стабильное разрешение совпадений. На каждой итерации отправки читается актуальное хранилище, поэтому завершение старого запроса не стирает работу нового экземпляра. Старый массив мигрирует с сохранением UUID/порядка; исходный ключ удаляется после успешного копирования всех событий.

Два экземпляра могут отправить один UUID повторно. Это доставка с повторениями: сервер проверяет совпадение содержимого и уникальность `(session_id, client_event_id)`, поэтому подтверждённое действие не должно дублироваться в журнале. Это не распределённая транзакционная очередь. Почти одновременные записи разных вкладок получают стабильный порядок, но восстановить человеческую причинность двух одновременно действующих операторов нельзя. Учебную попытку следует вести одним оператором; старые вкладки предыдущей версии клиента перед обновлением нужно закрыть.

Остановка преподавателем и другие серверные 409 не удаляют неподтверждённые действия из локального хранилища. Их нельзя выдавать за принятые сервером или добавлять к уже завершённому отчёту. Необработанный черновик всё ещё хранится отдельно: одновременное редактирование одного поля в двух вкладках использует последнее сохранённое значение. Это ограничение черновиков, а не потеря подтверждённых событий.

LocalStorage ограничен квотой, доступен только на этом устройстве и удаляется при очистке данных браузера. Повреждённые записи не отправляются как доверенные события. Данные разных пользователей и разных попыток используют отдельные ключи; сервер повторно проверяет владельца каждого запроса. Потеря авторизации не обходится локальной очередью.
