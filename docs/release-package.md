# Архив исходников и демонстрации

`deliverables/kontur-dds-source.zip` — замороженная RC1; `deliverables/kontur-dds-source-rc2.zip` — замороженный снимок RC2; `deliverables/kontur-dds-source-rc3.zip` — снимок RC3. Текущий source ZIP собирается отдельно как RC4 после сверки Q&A. ZIP-файлы не включены в Git. Source ZIP **не автономный установщик**: Python-окружение, пакеты, Docker image и AI-модели в него не включены. Публичный Git-снимок дополнительно заменяет производный классификатор заказчика пустым маркером и имеет отдельную историю.

## Создание и проверка

Из корня проекта, стандартным Python 3.12/3.13, укажите новое versioned имя. Замороженный RC1 файл по умолчанию не перезаписывается:

```sh
python3 scripts/package_release.py --output deliverables/kontur-dds-source-rc2.zip
```

Скрипт создаёт ZIP атомарно и отказывает, если ZIP или его соседние метаданные уже существуют: для нового содержимого выберите новый номер версии либо сначала сохраните старый комплект отдельно. Он повторно строит архив из того же снимка входов и сравнивает байты. Имена отсортированы, время и права файлов нормализованы. Одинаковые входные байты и совместимая реализация ZIP/zlib дают одинаковый архив. В ходе активных изменений кода архив следует пересобрать перед сдачей; он не обновляется автоматически.

Внутри архива каталог `kontur-dds/`, файл `OFFLINE-PREREQUISITES.txt` и `PACKAGE-MANIFEST.json` с точным перечнем, размером, SHA256 и правами каждого файла. Для RC1 рядом с ZIP сохранены `release-package-manifest.json` и `release-package-validation.json`; для RC2 используются отдельные `kontur-dds-source-rc2.manifest.json` и `kontur-dds-source-rc2.validation.json`. RC3 использует собственные `kontur-dds-source-rc3.manifest.json` и `kontur-dds-source-rc3.validation.json`. Эти внешние отчёты не включаются обратно в ZIP, чтобы не создавать рекурсивную зависимость и не перезаписывать RC1.

Проверка распаковывает архив во временный каталог, сверяет полный набор путей и хеши, обязательные точки входа, синтаксис Python и shell, а также ссылки готового HTML на JS/CSS. Приложение из чистого архива не запускается без отдельно подготовленных зависимостей — такой запуск не заявляется выполненным.

## Что входит

- Backend-код, синтетические сценарии и знания, нормализованный классификатор, тесты, `pyproject.toml` и `uv.lock`.
- Frontend-код и lockfile, готовая `frontend/dist`, подготовленные короткие WAV.
- Скрипты запуска, проверок, backup/restore, локального AI и сборки презентации.
- Публичная документация, отчёты измерений, выбранные исследовательские записки и решения. Для воспроизведения синтетического сравнения моделей RC2 включены ровно шесть файлов из `research/model-comparison/`: preregistration, holdout, prompt, методика, манифест источника модели и версия инструментов.
- Редактируемый PPTX, PDF защиты, выбранные реальные снимки экрана, озвученный монтаж ранней версии и сценарий видеодемонстрации.
- `.env.example` с явно демонстрационными значениями. Реальный `.env` не включается.

## Что исключается

`.git`, `node_modules`, виртуальные окружения, кэши, `runtime`, `models`, модели/веса, исходные записи Q&A, скачанные документы заказчика, рабочие SQLite/backup-файлы, cookie/токены из БД, настоящие env-файлы и приватный `research/source-manifest.json` с абсолютными путями. Включение определяется положительным списком путей и расширений; файл вне разрешённых каталогов и форматов автоматически в поставку не попадает.

Символические ссылки не упаковываются. Недопустимы абсолютные имена, `..`, обратные слеши и дублирующиеся ZIP-пути. Есть ограничения размера 32 МиБ на файл и 96 МиБ исходного содержимого. Короткие заранее синтезированные WAV и конкретный проверенный монтаж `deliverables/kontur-dds-demo-montage.mp4` разрешены; иные видеозаписи и тяжёлые веса не переносятся.

Высокоуверенные шаблоны ключей, приватных ключей и URL со встроенными HTTP-паролями проверяются до записи, включая XML внутри PPTX. Найденное значение не печатается. Единственное точное исключение — известный синтетический localhost URL в тесте `backend/tests/test_ai.py`; другой файл или другое значение по-прежнему отклоняется. Это ограниченный скрининг, а не доказательство отсутствия всех возможных секретов. Демопароль `Demo112!` намеренно публичен, относится к синтетическим учётным записям и не маскируется как производственный секрет.

В Markdown-копиях абсолютный путь рабочего каталога заменяется на `.`, домашний путь разработчика — на `<USER_HOME>`. Оригиналы проекта не меняются; преобразования и исходные SHA256 перечислены в manifest. Код, JSON и документы не переписываются скрыто. Оставшийся приватный домашний путь приводит к отказу упаковки.

## Запуск после распаковки

Минимальная подготовка с доступом к пакетным репозиториям, если используется включённая браузерная сборка:

```sh
cd kontur-dds
uv sync --project backend --frozen --no-dev
./scripts/start.sh --offline
```

Нужны совместимый Python 3.12/3.13 и `uv`. Затем сервер доступен на `http://127.0.0.1:8000`. `--offline` означает отсутствие попыток установки зависимостей при старте; нужное окружение **уже должно существовать** как `backend/.venv`. Для полной пересборки выполнить `./scripts/start.sh` с Node.js 22/npm и доступом к источникам зависимостей.

Для полностью закрытой машины заранее подготовить подходящие для её ОС/архитектуры Python-пакеты либо отдельный образ. Копирование `.venv` с Mac на Linux не является поддержанным способом установки. Dockerfile включён как рецепт; готовый Docker image и его офлайн-работоспособность не входят в доказательства этой поставки.

AI опционален: без отдельных весов и runtime доступны учебный цикл, правила и текстовый доклад. При подключении AI следовать `docs/local-ai.md` и `docs/local-tts.md`. Настройка закрытого контура и целевых компьютеров требует отдельного испытания.

## Что требуется для сдачи

PDF задания, раздел 18 на последней странице, перечисляет четыре ссылки: репозиторий с кодом, презентация, прототип и сопроводительная документация в DOCX/PDF. Локальный ZIP сам по себе не создаёт эти ссылки и ничего не публикует.

В Q&A около 48:56–50:05 дополнительно допускают видеопрезентацию продукта или запись экрана со звуком до пяти минут. [Запись заказчика](https://drive.google.com/file/d/1qpYkmGuSVKPBrBQgC_WB5luTcDzr0ZW9/view). Это уточнение изучено по машинной расшифровке и не заменяет список из PDF. Озвученный монтаж 3:56 относится к варианту видеопрезентации; его нельзя выдавать за непрерывную запись выполнения задания или демонстрацию нового разбора RC2. `docs/demo-script.md` — сценарий отдельной записи, не готовый ролик.
