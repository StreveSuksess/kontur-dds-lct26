# Пустые формы пилота

Связанный документ: [протокол](../pilot-protocol.md). Формы содержат **только заголовки**, ни одного наблюдения. Они не являются выгрузкой приложения и не импортируются обратно в него.

CSV: UTF-8, разделитель запятая, первая строка — имена полей. Импортировать в Excel/LibreOffice как CSV с UTF-8, не полагаться на региональный автоматический разделитель. Идентификаторы и цитаты импортировать как **текст**, время/числа — отдельно с указанным типом. Цитаты, содержащие запятые/переносы строк, сохранять стандартным CSV-экранированием двойными кавычками. Формулы в CSV не нужны; строки участника не исполнять как формулы.

## Общие правила

- Одна строка — указанная ниже единица наблюдения. ID стабильны, не переиспользуются; таблицы соединяются по `study_id`, `case_id`, `attempt_id`, `criterion_id`, где они применимы.
- `study_id` — код исследования; `protocol_version` — замороженная версия; `session_id` — код исследовательской сессии, **не** ID попытки приложения.
- `participant_id` — T01/T02/L01–L08; ФИО/телефоны здесь не нужны. `role` = `teacher` / `learner`. `observer_id` / `rater_id` — отдельные коды наблюдателя/эксперта.
- `task_id` — T_PREP, T_ASSIGN, T_OBSERVE, T_REVIEW_A–D, T_NEXT или L_BASELINE, L_PRACTICE, L_TRANSFER, L_RECOVERY, L_DELAYED. При добавлении задачи сначала внести её в замороженный план.
- Для парной подготовки в `T_PREP` указать `case_id=S1_v1` или `S2_v1` и `condition=manual` либо `rc1/rc2`. Интервалы обеих сторон фиксировать одинаково; без этих строк полную стоимость занятия не рассчитывать.
- `condition` = `manual` / `rc1` / `rc2` / `not_applicable`; точная сборка берётся из листа фиксации. Отдельный номер волны указывается в `study_id`.
- `case_id` — версия исследовательского материала, например `A_v1`; `attempt_id` — UUID попытки приложения, если она существует. Ручной пакет может не иметь UUID, тогда поле пустое.
- UTC — ISO 8601 с `Z`; длительности — секунды, десятичная точка. `true` / `false` — логические значения. Пустое поле означает неизвестно/неприменимо; **не ноль**. Причину пропуска указывать в соответствующей строке заметки/`missing_reason`.
- Сырые заметки, независимые экспертные решения и исходный системный отчёт не перезаписывать консенсусом. Для исправления строки сохранять предыдущую версию файла и журнал поправок; итоговый анализ строить из явно выбранной версии.

## observations.csv — одна наблюдаемая ситуация

Используется для качественных событий, а не для подсчёта участников. Несколько строк одного ученика не превращаются в независимых учеников.

| Поля | Тип / как заполнять |
|---|---|
| `observation_id` | Уникальная строка, например O001. |
| `study_id`, `protocol_version`, `session_id`, `participant_id`, `role`, `task_id`, `condition`, `case_id`, `attempt_id`, `observer_id` | Связи и контекст по общим правилам. |
| `elapsed_seconds` | Число ≥0 от начала соответствующей задачи; это не elapsed_seconds серверного события, если начало часов отличается. |
| `observation_type` | `action`, `quote`, `error`, `hesitation`, `help`, `recovery`, `technical`, `post_task_probe`. |
| `observed_action` | Только наблюдаемый факт: что нажал/прочёл/сохранил и результат. Не «не понимает систему». |
| `participant_quote` | Дословная обезличенная цитата; не реконструировать отсутствующую запись. |
| `help_level` | 0 — без помощи; 1 — повтор условия без новой информации; 2 — подсказка направления/следующего действия; 3 — выполнение модератором. Не путать с встроенной подсказкой: её записать отдельным событием и отметить при оценке самостоятельности. |
| `help_text` | Что именно сказал/сделал модератор или какая встроенная подсказка использована. |
| `issue_category` | `navigation`, `terminology`, `rubric_ambiguity`, `evidence_search`, `false_feedback`, `correction`, `draft_vs_action`, `workflow`, `export_reentry`, `technical`, `none`, `other`. |
| `criterion_id` | ID критерия, если наблюдение связано с конкретной оценкой; иначе пусто. |
| `evidence_locator` | Ссылка на обезличенный файл/кадр/серверный event ID. Разные виды источников явно подписывать. |
| `observer_interpretation` | Гипотеза наблюдателя, отдельно от фактов. Например возможная причина; не диагноз и не мнение участника. |

## task-outcomes.csv — одна задача одного участника

| Поля | Тип / как заполнять |
|---|---|
| `study_id`, `protocol_version`, `session_id`, `participant_id`, `task_id`, `condition`, `case_id`, `attempt_id` | Контекст; комбинация study/session/task/case должна быть уникальна. Повтор оформлять новым task_id. |
| `started_at_utc`, `ended_at_utc`, `wall_seconds` | Время начала/окончания и их разница. Полное время включает ожидание техники; исследовательскую паузу отметить и показать отдельно в time-cost. |
| `time_limit_seconds` | Заранее установленный лимит, не подгонять после результата. |
| `completion` | `complete`, `incomplete`, `timeout`, `withdrawn`, `not_run`. Ошибочно завершённая попытка = complete, но не успешная. |
| `independent_success` | true только при завершении, выполнении всех заранее критических условий и отсутствии подсказок по действиям/содержанию. Если не удалось оценить — пусто. |
| `max_help_level` | Максимальная помощь 0–3 по определениям выше. Встроенная содержательная подсказка исключает самостоятельный успех даже без помощи модератора. |
| `critical_errors` | Неотрицательное целое по согласованной рубрике. Пусто до экспертной оценки, не 0 по умолчанию. |
| `applicable_steps`, `correct_steps` | Целые числа по заранее зафиксированному чек-листу; correct ≤ applicable. Не менять число шагов ради улучшения результата. |
| `participant_claimed_complete` | true/false из слов или действия участника; независимо от объективного успеха. |
| `technical_blocker` | Краткое описание технического препятствия либо `none`; не исключать такие строки автоматически. |
| `missing_reason` | Причина пропуска/неоценённого показателя; например нет журнала, отказ от задачи, критерий спорный. |

## adjudication.csv — одно решение одного эксперта по одному критерию

| Поля | Тип / как заполнять |
|---|---|
| `judgment_id` | Уникальный ID решения. |
| `study_id`, `case_id`, `attempt_id`, `criterion_id`, `rubric_version` | Стабильные ключи. Rubric_version не заменять текущей версией из редактора. |
| `critical` | true/false из рубрики, определённой до наблюдения, не по впечатлению после ошибки. |
| `phase` | `independent`, `consensus`, `product_review`. Первые два — эталонный разбор; третье — действие во время проверки продукта. |
| `rater_id` | T01, T02; для согласованного решения `T01+T02`. Внешний независимый арбитр получает свой ID только если действительно участвовал. |
| `blinded_to_system` | Был ли скрыт системный вывод во время решения. true не означает отсутствие памяти о пакете — это ограничение отражено в протоколе. |
| `expert_verdict` | `pass`, `fail`, `unresolved`, `not_applicable`. |
| `reason` | Краткое основание: какое действие/смысл и почему соответствуют критерию. Для unresolved — чего не хватает. |
| `evidence_event_ids` | ID доказательств через `|`; не добавлять выдуманные события, не путать реплику контакта с репликой ученика. |
| `original_system_verdict` | `pass`, `fail`, `review`, `not_applicable` или пусто. **При независимой разметке скрыть/оставить пустым**, присоединить только к аналитической копии после фиксации экспертного решения. |
| `final_system_verdict` | Вердикт конкретного критерия после экспертного пересмотра, если система его поддерживает. В RC1 оставить пустым: общий балл не означает подтверждения каждого критерия. |
| `source_judgment_ids` | Для consensus: оба исходных judgment_id через `|`; независимые строки сохраняются. |
| `disagreement_reason` | `none`, `evidence_missing`, `rubric_ambiguous`, `fact_interpretation`, `speaker_or_time`, `other` + пояснение в reason. |

Для расчёта ошибок выбрать одну consensus-строку на case/attempt/criterion и присоединить неизменённый исходный системный вывод. Независимые и product_review-строки **не суммируются** с consensus как новые случаи. Системный review не равен expert fail. Общую оценку преподавателя хранить в отдельном исходном отчёте; не размножать её по критериям.

## time-cost.csv — один непересекающийся интервал одного человека

| Поля | Тип / как заполнять |
|---|---|
| `interval_id`, `study_id`, `session_id`, `participant_id`, `role`, `condition`, `task_id`, `case_id`, `attempt_id` | ID интервала и контекст. При общей подготовке case/attempt могут быть пустыми. |
| `scope` | `shared_setup` — один раз на группу/материал; `per_case` — конкретная проверка; `research_only` — опрос/заполнение исследовательской формы, не обычная работа. |
| `cost_category` | `scenario_preparation`, `rubric_calibration`, `evidence_review`, `correction`, `feedback`, `administration`, `technical_wait`, `research_probe`. |
| `started_at_utc`, `ended_at_utc`, `duration_seconds` | Конец ≥ начало; duration — разница. Пересекающиеся интервалы одного человека проверить до суммирования. |
| `active_human` | true для человеческого труда; false для ожидания без работы. Если при ожидании делает другую задачу, фиксировать эту задачу, не двойной труд. |
| `recording_method` | `observer_timer`, `screen_recording`, `self_estimate`; оценки по памяти отдельно от измеренных секунд. |
| `notes` | Причина паузы, неопределённость измерения, пакет общих материалов/число случаев для распределения подготовки. |

Исследовательское заполнение CSV исключается из продуктовой стоимости; само принятие экспертного решения и составление необходимого объяснения включаются. Иначе новая функция получит искусственную экономию за счёт исключения содержательной работы. Для ручного и продуктового условий использовать одинаковое правило.

## Перед анализом

1. Проверить уникальность ключей, версии, пропуски и временные интервалы; не исправлять неясное значение догадкой.
2. Посчитать участников и попытки отдельно от критериев/событий. Показать незавершённые и технически прерванные задачи.
3. Заморозить независимые оценки до соединения с автоматическими. Сохранить несогласованные критерии.
4. Показать абсолютные числители/знаменатели и индивидуальные времена. При нулевом знаменателе писать «не оценено».
5. Сопоставить результаты с заранее заполненным листом фиксации; новые объяснения явно пометить как разведочные.
