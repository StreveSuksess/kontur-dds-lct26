# Браузерная проверка интерфейса RC3

26 сентября 2026 проверены новый предпросмотр сценария, наблюдение первого решения по карточке и объяснение подбора следующей практики. Проверка выполнялась настоящим Chromium headless 148.0.7778.96 через Playwright, с текущей production-сборкой Vite и локальным FastAPI. Это техническая проверка интерфейса на синтетических данных; преподаватели и учащиеся в ней не участвовали.

## Среда и воспроизводимость

- Отдельный сервер слушал только `127.0.0.1:54366`; использовалась новая SQLite-база, `DEMO_MODE=true`, `AI_MODE=rules`.
- Проверены размеры окна 1440 × 1000 и 390 × 844. Узкое окно проверяет переносы и размещение элементов; это не испытание на физическом смартфоне.
- Вход преподавателя выполнен через форму интерфейса. Сценарии, назначения и события попыток подготовлены через публичные локальные API с отдельными преподавательской и ученическими сессиями. Выполнение всего упражнения кликами по АРМ в этот прогон не входило.
- Browser-контекст разрешал запросы только к указанному localhost. В основном прогоне зарегистрировано 0 внешних запросов и 0 ошибок `pageerror`.
- Использован уже установленный Chromium. Дополнительные браузеры не скачивались; системные разрешения macOS и Telegram не затрагивались.

## Предпросмотр перед утверждением

Проверены открытие окна преподавателем и следующие состояния:

- Лимит открытия 45 секунд и лимит завершения 240 секунд показываются раздельно.
- Длинные описание карточки и ответ контакта сохраняются полностью. Переносы строк и длинный идентификатор без пробелов не создают горизонтального переполнения окна, включая ширину 390 пикселей.
- `unknown` отображается как «Нет сведений», `yes` — «Есть», `no` — «Нет». Проверены три отдельных сценария.
- Видны приветствие и ответ каждого из двух контактов, а также два разрешённых подтверждающих контакта у смыслового критерия. Проверены имена, учебные номера и пояснение о предварительном подтверждении.
- Критичность, варианты формулировок и порядок статусов читаемы. Кнопки редактирования и утверждения остаются видимыми при прокрутке.
- Escape закрывает окно. Полная клавиатурная навигация и экранный диктор этим прогоном не проверялись.

## Первое решение по карточке

Проверены отдельные завершённые попытки с первым `accepted`, первым `rejected` и без обоих действий. В последнем случае сохранены открытие карточки и статус `responding` с текстом «Карточка принята»; интерфейс корректно показывает «Не зафиксировано».

Дополнительный прогон отделяет время решения от времени открытия: карточка открыта сразу, первое `accepted` сохранено через 2,114318 секунды, позднее сохранён `rejected`. Наблюдение показывает первое решение «Принята · 0:02», а не последнее состояние. Преподаватель и ученик видят одинаковое наблюдение; в ученическом отчёте отсутствует кнопка подтверждения общего итога.

Для попытки с событием `connection_restored` показано предупреждение, что время серверной записи может отличаться от времени действия. Это проверка отображения зарегистрированного события; реальное отключение сети здесь не моделировалось.

Снимок: [первое решение с ненулевым временем](../deliverables/assets/rc3-report-first-decision.png). Подпись явно относит время к началу учебной попытки и отделяет наблюдение от оценки открытия карточки.

## Подбор следующей практики

Через API подготовлены три завершённые попытки другого учебного пользователя: остальные критерии выполнены, факт направления бригады явно отрицается. Во всех трёх исходных отчётах автоматический результат не требует дополнительной проверки смысла; это контролируемая тестовая конструкция, а не независимая экспертная разметка.

Исходный сценарий после попыток архивирован. При отсутствии утверждённого кандидата с тем же критерием API возвращает пустой список, а интерфейс показывает причину и «В показанной подборке не покрыты критерии». Затем создан и утверждён один кандидат с точным совпадением ID и названия факта. Он появляется как единственный вариант; рядом отображается конкретный совпавший критерий.

Снимок: [подбор с объяснением совпадения рубрики](../deliverables/assets/rc3-recommendation-match.png). Ответ ученического API рекомендаций дополнительно проверен на отсутствие `required_facts`, `reference_response` и `confirmed_by_contact_ids`.

Частичное покрытие нескольких слабых критериев, граница пяти предложений, ветка подбора только по профилю/уровню и все комбинации ролевых ограничений не проверялись в браузере этим прогоном; для них используются отдельные серверные регрессии. Совпадение рубрики не подтверждает перенос навыка на новую ситуацию.

## Результат и ограничения

Целевые браузерные проверки пройдены; снимки просмотрены визуально. Для проверенных состояний не обнаружены потеря текста, смешение unknown/yes/no, горизонтальное переполнение предпросмотра или подмена первого решения последующим статусом. Продуктовый код по результатам этого прогона не изменялся.

Проверка охватывает Chromium на машине разработки. Firefox, Яндекс.Браузер, целевые Windows/Linux, физические мобильные устройства, реальная SIP-телефония и пользовательский пилот остаются вне этого протокола.
