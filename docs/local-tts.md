# Локальная озвучка реплик

Дополнительный сервис произносит полный текст ответа учебного собеседника голосом macOS Milena. Он не генерирует содержание реплики, не меняет её смысл и не влияет на оценку. Звук возвращается как WAV; телефонный разговор остаётся программной симуляцией.

## Запуск

Требуются macOS, Python 3, системные `say` и `afconvert`, установленный русский голос Milena. Внешние Python-библиотеки и API не нужны.

```sh
./scripts/local_ai/start_tts.sh
curl --noproxy '*' http://127.0.0.1:11436/health
```

Адрес привязан к `127.0.0.1`, порт по умолчанию `11436` (`--port` позволяет изменить). Сервис предназначен для локального backend-прокси, браузер работает через авторизованный API приложения. Прямой loopback API не содержит пользовательской авторизации; его не следует выставлять наружу или использовать как отдельный сетевой сервис.

На другой ОС `/health` возвращает `status: unavailable`, `available: false`, `reason: macos_required`; синтез возвращает HTTP 503. При отсутствии голоса причина `milena_voice_missing`. Успешная работа на Linux не имитируется. Для целевого Linux-класса нужен отдельно интегрированный и проверенный TTS-движок. После установки отсутствующего голоса сервис нужно перезапустить.

## Контракт

- `GET /health`: доступность, голос, платформа, `busy`, `max_text_chars: 1999`, `timeout_seconds: 20`.
- `POST /synthesize`, `Content-Type: application/json`, тело `{"text":"Дежурный инженер слушает."}`. Непустая строка до 1999 символов, JSON до 16 КиБ. Ответ HTTP 200 `audio/wav`, `Cache-Control: no-store`.
- Некорректный JSON — 400, большой запрос — 413, иной Content-Type — 415, пустой/длинный текст или управляющие символы — 422.
- Один синтез одновременно; конкурирующий запрос — 429 `speech_engine_busy`, `Retry-After: 1`. Клиент сохраняет возможность читать текст, пока звук недоступен.
- Совокупный тайм-аут `say` и `afconvert` — 20 секунд, превышение — 504. Ошибка системного движка — 503.

Текст записывается в отдельный временный UTF-8 файл и передаётся `say` через `-f`. Все процессы запускаются массивом аргументов, без shell. Временный каталог автоматически удаляется при успешном синтезе и ошибках. Текст реплик и аудиофайлы сервер постоянно не хранит и не записывает в логи. Дополнительного скачивания моделей при синтезе нет.

Backend приложения должен проверять доступ пользователя к попытке и тип события `contact_message` перед получением звука; исходный текст берётся из сохранённого события, а не из произвольного браузерного ввода. URL интеграции: `GET /api/sessions/{session_id}/events/{event_id}/audio`.

## Проверено 19 сентября 2026

На текущем Mac голос Milena обнаружен. Два разных русских текста дали настоящие моно WAV 22050 Гц:

| Текст | Длительность звука | Время синтеза | Размер |
|---|---:|---:|---:|
| Представление дежурного и просьба назвать адрес | 4,45 с | 0,756 с | 200 294 байта |
| Подтверждение, отправка бригады, адрес и уточнение пострадавших | 10,36 с | 0,722 с | 461 180 байт |

Python `wave` прочитал оба результата. Это технический smoke-тест, не экспертная оценка дикции или нагрузочный тест класса. Текст 2000 символов получил 422. Два одновременных запроса получили 200 и 429; успешный запрос вернул WAV 2 737 766 байт. Тестовые файлы сохранены только в `/tmp/lcthack-tts-test-{1,2}.wav`.

При первом запуске выявлена задержка стандартного `HTTPServer` на `socket.getfqdn('127.0.0.1')`. Для локального TTS используется `LoopbackServer`: привязка сокета без DNS, явное имя `localhost`. Такой же фикс внесён в `speech_server.py`. Работающий процесс Whisper при этом не перезапускался: новая версия ASR-кода вступит в силу при следующем штатном перезапуске. Поведение распознавания не менялось.
