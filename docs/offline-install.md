# Офлайн-установка: проверяемый комплект для текущего хоста

Скрипты разделяют онлайн-подготовку и первую установку Python-зависимостей без индекса пакетов. Комплект привязан к платформе и CPython 3.12. Для текущей машины подготавливается macOS arm64; такой wheelhouse не является проверенным Linux x86_64-дистрибутивом.

Это не установщик на пустую операционную систему. **CPython 3.12 с модулями `venv` и `ensurepip` должен быть установлен заранее.** Python runtime, системные библиотеки, исходный код приложения и модели AI в wheelhouse не входят. Целевая машина получает исходники проекта с `backend/app`, тремя JSON-файлами `backend/data`, `backend/pyproject.toml`, `backend/uv.lock` и скриптами установки; `.env`, рабочие БД и реальные материалы заказчика переносить для демонстрационного первого запуска не нужно.

## Подготовка при наличии интернета

Предварительно соберите `frontend/dist` обычным процессом проекта. Подготовке нужен установленный `uv`; целевой офлайн-установке `uv`, Node.js и npm уже не нужны. Из корня проекта:

```sh
python3.12 scripts/prepare_offline.py \
  --python python3.12 \
  --destination runtime/offline-wheelhouse
```

Если Python 3.12 установлен через uv и не находится в PATH, передайте полный путь к установленному интерпретатору. На машине разработки можно использовать `backend/.venv/bin/python` для создания нового временного окружения: существующий venv не обновляется.

Подготовка выполняет `uv export --frozen --offline` из существующего lockfile, включая dev-группу для проверок. Требования содержат точные версии и SHA-256. Во временном venv через `ensurepip` запускается `pip download --require-hashes --only-binary=:all:`; неподходящие платформенные markers пропускаются. Затем копируется уже готовый интерфейс. [Документация pip download](https://pip.pypa.io/en/stable/cli/pip_download/), доступ 19.09.2026.

Скрипт удаляет из окружения унаследованные настройки pip/uv индексов и `trusted-host`, отключает пользовательский pip config и использует HTTPS PyPI. Проверка TLS не отключается. При корпоративном CA можно передать `--cert /путь/ca.pem`; этот файл не включается в комплект. Современный pip на Python 3.10+ поддерживает системные сертификаты через truststore; если `ensurepip` поставляет старую версию, используйте доверенный CA bundle вместо обхода проверки сертификата. [Документация HTTPS certificates](https://pip.pypa.io/en/stable/topics/https-certificates/), доступ 19.09.2026.

Каталог назначения должен быть новым; существующий комплект не перезаписывается. Состав:

```text
runtime/offline-wheelhouse/
  manifest.json        # платформа, хеши lockfile/pyproject и каждого файла
  requirements.txt     # точные зависимости из uv.lock, с хешами
  wheels/*.whl         # только колёса текущей платформы и universal wheels
  frontend-dist/       # готовый интерфейс и локальные статические ресурсы
```

Каталог `runtime/` исключён из Git: при передаче офлайн-комплекта его нужно копировать явно. Manifest проверяет целостность файлов, но не является цифровой подписью или доказательством происхождения поставки. Source commit/version следует фиксировать отдельно. При изменении lockfile/pyproject или интерфейса подготовьте новый комплект; установленная копия интерфейса не обновляется автоматически вслед за разработкой.

## Первая установка без интернета

На подготовленной машине той же платформы, из корня переданного проекта:

```sh
python3.12 scripts/install_offline.py \
  --python python3.12 \
  --bundle runtime/offline-wheelhouse \
  --venv backend/.venv \
  --smoke
```

Установщик отказывается изменять существующий venv. Для независимой проверки используйте новый путь, например `runtime/offline-validation/.venv`. Он проверяет платформу, Python major/minor, SHA-256 файлов комплекта и соответствие исходных `uv.lock`/`pyproject.toml`; затем создаёт новый venv и выполняет:

```text
pip install --no-index --no-cache-dir --find-links <bundle>/wheels
            --only-binary=:all: --require-hashes -r <bundle>/requirements.txt
pip check
```

В процессе установки дополнительно запрещены Python-вызовы `socket.connect`, `socket.connect_ex` и `getaddrinfo`: случайный запрос пакетов в сеть не сможет успешно выполниться. `ensurepip` использует встроенные в Python пакеты. Это ограничение процесса, не изменение сетевых настроек всей машины. [Документация pip install](https://pip.pypa.io/en/stable/cli/pip_install/), доступ 19.09.2026.

Если установка пакетов завершается ошибкой, созданный этим запуском venv удаляется. Если после успешной установки падает smoke, окружение сохраняется для диагностики, команда возвращает ошибку. Повторный запуск требует нового пути; опции принудительного обновления существующего venv нет.

## Запуск подготовленного приложения

Для новой демонстрационной поставки без `backend/.env`, в bash/zsh из корня проекта:

```sh
DDS_PROJECT_DIR="$PWD"
export STATIC_DIR="$DDS_PROJECT_DIR/runtime/offline-wheelhouse/frontend-dist"
export DATABASE_URL="sqlite:///$DDS_PROJECT_DIR/backend/var/offline-demo.db"
export DEMO_MODE=true
export AI_MODE=rules
export AI_ENDPOINT=""
export ALLOWED_ORIGINS="http://localhost:8000,http://127.0.0.1:8000"
cd backend
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Открыть `http://127.0.0.1:8000`. Один worker соответствует проверенному режиму MVP. Это отдельный новый демонстрационный файл БД; он не восстанавливает рабочие данные. Для существующих данных используйте отдельную процедуру backup/restore. Демонстрационные пользователи создаются при `DEMO_MODE=true`; это не production-режим.

Эти команды не меняют `scripts/start.sh`: тот сохраняет свой прежний сценарий установки/запуска. В показанном варианте статика берётся прямо из wheelhouse, поэтому копировать её поверх текущего `frontend/dist` не нужно.

## Что проверяет smoke

`--smoke` запускает новый интерпретатор установленного venv. Скрипт копирует исходные `app` и три JSON в временный каталог, не копирует `.env`, использует временную SQLite БД и блокирует исходящие Python-соединения. Импортируются FastAPI и бинарные компоненты серверного стека. Через ASGI TestClient проверяются health, выдача index/assets, вход, назначение, старт, телефонный доклад, события, сдача на 100 баллов, преподавательская оценка и рекомендации.

Это проверка свежей установки и жизненного цикла без сети на уровне Python-процесса. Она не заменяет браузерную проверку JavaScript, отключение Wi-Fi на уровне ОС или тест физического учебного класса. PostgreSQL-сервер не поднимается; наличие psycopg-wheel не означает проверку PostgreSQL-развёртывания.

## Подтверждённый прогон 19.09.2026

На текущем хосте подготовлен `runtime/offline-wheelhouse`: **31 wheel**, **15 685 114 байт** вместе с интерфейсом/manifest, CPython **3.12.13**, macOS **arm64**. Затем выполнена первая установка в новый `runtime/offline-validation/.venv` с `--no-index` и блоком Python-соединений. `pip check`: `No broken requirements found`.

Smoke завершился успешно: **0 попыток сети**, временная БД, 8 сценариев, index и 2 связанных JS/CSS-ресурса, полный текстовый учебный цикл на **100 баллов**, преподавательский разбор и рекомендации. Проверено отклонение другого target architecture, повреждённого файла и существующего рабочего `backend/.venv`; `pyvenv.cfg` последнего не изменился. Исходный рабочий файл БД в проверке не открывался.

Локальные доказательства: `runtime/offline-install-validation.log` и `runtime/offline-validation/result.json`. Они не включены в Git автоматически. Повтор smoke без переустановки:

```sh
runtime/offline-validation/.venv/bin/python -I scripts/offline_smoke.py \
  --bundle runtime/offline-wheelhouse
```

## Другой целевой компьютер

Для Linux x86_64, Windows или другой версии Python нужен отдельный комплект. Надёжный путь — подготовить wheelhouse на том же семействе ОС/архитектуре/Python, затем выполнить свежую офлайн-установку и smoke на целевом устройстве. Python 3.12, `venv`/`ensurepip` и необходимые системные пакеты ОС нужно подготовить заранее. Linux x86_64 здесь **не проверен**; доступность бинарных wheels, glibc и библиотек проверяется там.

Cross-download через pip `--platform`, `--python-version`, `--implementation`, `--abi` технически возможен, но сам по себе не подтверждает работоспособность, а маркеры окружения требуют внимания. Текущий скрипт намеренно готовит native-platform bundle, без обещания универсального пакета. [Документация pip download](https://pip.pypa.io/en/stable/cli/pip_download/), доступ 19.09.2026.

Локальные LLM/ASR/TTS — отдельный необязательный комплект с собственными runtime/весами и проверками платформы. Здесь они не скачиваются и не устанавливаются. Текстовый учебный цикл работает в `rules`/`templates` без них; наличие wheelhouse не следует называть готовностью голосового AI на другом ПК.
