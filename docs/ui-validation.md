# Проверка интерфейса в браузере

Дата: 19 сентября 2026. Реальные действия через Codex In-app Browser, локальный сервер `127.0.0.1:8000`, Mac arm64. Это инженерная проверка синтетического прототипа, не пользовательское исследование и не педагогическая аттестация.

## Подтверждённые потоки

- Преподаватель назначил утверждённый сценарий; учащийся увидел задание, начал попытку и открыл готовую карточку.
- Номер9999 не соединял;2001 соединял с учебным должностным лицом. Доклад передавался отдельно, ответ появлялся в журнале. После принятых статусов/завершения звонка сдача открыла отчёт100/100; раскрытие критерия показало соответствующие события. Попытка заняла46секунд при учебном лимите180секунд; это один синтетический прогон.
- Повтор создал новую попытку с отдельной историей. Нажатие «Прослушать ответ» запросило локальный WAV; проверен успешный запрос/возврат UI из загрузки, субъективная разборчивость звука не оценивалась.
- Загрузка реального WebM через file chooser → Whisper small → редактируемый распознанный текст,2.048секунды в UI. До «Вставить в доклад» поле доклада пустое; без отдельной отправки текст не стал событием. MIME `video/webm` нормализован в аудиотип. Живой микрофон/разрешение браузера не тестировались.
- Учебный сервер принудительно остановлен; отправленный статус остался в локальной UUID-очереди. После запуска сервера записался **ровно один раз**, с тем же UUID. Маркер `connection_restored` содержал64.35секунды недоступности по клиенту (включая запуск сервера). Текст нового черновика сохранился после перезагрузки страницы. Системная сеть пользователя не отключалась.
- Найден и исправлен пробел: новый черновик после восстановления сначала оставался только локально. Повторная остановка сервера, изменение текста без отправки события и запуск подтвердили автоматический PUT после восстановления; точный текст прочитан из SQLite. Перезагрузка для синхронизации не потребовалась.
- Остановка преподавателем через отдельный HTTP-сеанс отразилась в открытом АРМ учащегося: статус остановлен, поля/телефон/сохранение заблокированы, разбор доступен. Остановленная попытка требует преподавательского разбора.
- UI «Создать вариант» реально вызвал local_llm Qwen3-1.7B:3.552секунды; адрес/тип/условие «Нет сведений о пострадавших» сохранены. Преподаватель добавил подтверждение факта контактом2001, сохранил версию2, увидел условие в preview и утвердил. Это проверка одного черновика, не оценка качества генератора на новых типах.

## Ограничения

Основной viewport1440×900. Нагрузка класса, screen reader и работа людей60+ здесь не воспроизводились. Сохранность зависит от доступности локального browserstorage; очистка профиля не является сетевым сбоем. Ограниченный смысловой анализ и авторская рубрика требуют методиста. Результаты автотестов/нагрузки/моделей приведены отдельными протоколами.

## Найденное ограничение AI и принятое изменение

Живой AI-review Qwen3-1.7B за8.755секунд предложил два ошибочных замечания к корректному докладу: одинаковый адрес назвал неполным, роль докладчика перепутал с адресатом. Цитаты были настоящими, выводы — ненадёжными. Балл100 остался неизменным. После этого раздел сделан свёрнутым и экспериментальным, сервер ограничен только спорными content/grammar-критериями; при отсутствии таких критериев модель не вызывается. Это ограничение риска, не доказательство качества оставшихся советов.

## RC2: покритериальное решение, 26 сентября 2026

Проверка выполнена в Codex In-app Browser на локальном сервере с отдельной синтетической SQLite-базой `runtime/rc2-browser-qa.db`. Две попытки назначены и завершены через отдельные авторизованные HTTP-сеансы; решение преподавателя и просмотр учащегося выполнены в интерфейсе. Это проверка пути приложения, не оценка качества преподавательских суждений.

- Начальный автоматический результат 25/100, критерий адреса `fail`, 0/18. В раскрытом критерии видны фактические и ожидаемые данные и отсутствие связанных событий. Набранное, но несохранённое решение получило метку «Не сохранено»; форма общего итога оставалась заблокированной даже после заполнения её комментария.
- После сохранения первого экспериментального решения `pass` с причиной расчёт по критериям стал 43/100. Исходные 25/100 и исходное `fail` остались доступны отдельно. Экран честно обозначил 43 как предварительное значение, а попытку исключил из рекомендаций до отдельного общего подтверждения. Поскольку в журнале не было передачи адреса, это решение затем было признано ошибочным в рамках теста; оно не служит примером правильной экспертной оценки.
- После явного подтверждения 43/100 учащийся в своей учётной записи увидел исходный вывод, решение преподавателя, автора, время, основание и отсутствие связанных событий. Элементы записи решения учащемуся не показывались.
- Преподаватель повторно проверил журнал, изменил критерий на `fail` с новым основанием. Экран показал предварительные 25/100, предупреждение об устаревшем прежнем итоге 43/100 и необходимость нового подтверждения. В этот момент `GET /analytics` учитывал только вторую завершённую попытку: `scored_sessions=1`, `average_score=25`; рекомендации имели `sample_size=1`. После повторного подтверждения 25/100 журнал показал оба решения и оба общих итога в порядке событий.
- Переключение на другую известную попытку показало её собственный отчёт 25/100 без решения преподавателя. Страница отчёта теперь монтируется по ID попытки и игнорирует запоздалый ответ предыдущего запроса, поэтому прежние данные не должны адресоваться другой попытке. Кросс-вкладочный конфликт ревизий дополнительно покрыт серверными тестами; конкурентный ручной браузерный прогон двух вкладок здесь не выполнялся.
- Дополнительный аудит выявил два сбоя обычного пути разбора. После исправления в браузере набрали одновременно черновики для «Действий с карточкой» и «Исходящего доклада», сохранили первый, затем второй без потери текста и без предупреждения о чужом конфликте. Кнопка сохранения уже сохранённого неизменённого решения стала недоступной; backend-тест отдельно подтвердил, что повтор идентичного запроса не создаёт ревизию или событие и не сбрасывает подтверждённый итог. Оба решения подтверждены общим итогом 25/100.
- Несохранённый черновик теперь можно явно сбросить: в браузере набрали основание по четвёртому критерию, получили метку «Не сохранено» и блокировку общего итога, нажали «Сбросить черновик». Текст исчез, кнопка подтверждения снова стала доступной; серверное решение не создавалось.

После RC2 браузерного теста выполнены `128` backend-тестов, `28` системных тестов, `9` тестов очереди и `4` теста состояния отчёта; сборка TypeScript/Vite успешна. Полный человеческий пилот, аудит доступности и целевой учебный класс остаются отдельными задачами.
