# Передача офлайн-комплекта macOS arm64

`scripts/package_offline.py` объединяет окончательный source ZIP с проверенным wheelhouse. Итоговая структура — один корень `kontur-dds/`, исходники и `runtime/offline-wheelhouse/`. Вложенный ZIP распаковывать не нужно. Первой прочитайте `OFFLINE-INSTALL-README.md` внутри поставки: там установка и запуск. Python 3.12 с `venv`/`ensurepip` для macOS arm64 устанавливается заранее; Python runtime и модели AI в архив не входят.

## Сборка после фиксации кода

Сначала выполнить онлайн-подготовку и свежую офлайн-установку по `docs/offline-install.md`. Если зависимости не изменились, готовые проверенные wheels можно использовать повторно. После последнего `frontend/dist` создайте НОВЫЙ снимок без сетевых запросов:

```sh
python3 scripts/package_offline.py refresh \
  --bundle runtime/offline-wheelhouse \
  --destination runtime/offline-wheelhouse-release
runtime/offline-validation/.venv/bin/python -I scripts/offline_smoke.py \
  --bundle runtime/offline-wheelhouse-release
```

Refresh проверяет хеши и точный состав исходного wheelhouse, неизменность `uv.lock`/`pyproject.toml`, копирует только записанные в manifest требования и wheels, заменяет снимок статики текущим `frontend/dist`. Существующий каталог назначения запрещён. При изменении зависимостей нужна новая онлайн-подготовка. Повторный smoke в уже установленном venv подтверждает обновлённые исходники и статику; это не новая первая установка пакетов.

После окончательной сборки source ZIP:

```sh
python3 scripts/package_offline.py package \
  --source-zip deliverables/kontur-dds-source.zip \
  --bundle runtime/offline-wheelhouse-release \
  --output deliverables/kontur-dds-macos-arm64-offline.zip
```

Комплект публикуется только если содержимое `frontend/dist` в source ZIP побайтно совпадает со снимком wheelhouse. Окончательные документы можно добавлять до сборки source ZIP, но изменение кода/статических ресурсов после smoke требует повторной проверки и нового снимка. Source ZIP должен содержать скрипты офлайн-установки.

## Проверки упаковщика

- Исходный ZIP: полный manifest, положительный список путей, SHA-256, сканирование очевидных секретов и приватных домашних путей, синтаксис Python/shell, ссылки на статические ресурсы.
- Wheelhouse: только manifest, requirements, `.whl` и разрешённая статика; лишние файлы отвергаются. Проверяются платформа, версии Python, хеши каждого файла, неизменность зависимостей.
- Отклоняются traversal, абсолютные пути, повторные записи ZIP, ссылки и специальные файлы; ограничен размер распакованного содержимого. Архивные данные не исполняются.
- Полный реестр `OFFLINE-PACKAGE-MANIFEST.json` включает исходники и дополнения. Повторная сборка тех же захваченных входных данных должна дать идентичные байты. Проверяется CRC и побайтное чтение готового ZIP.
- ZIP и отчёт `.validation.json` создаются только под новыми именами. Публикация каждого файла атомарная, через hard link; существующий файл, включая появившийся параллельно, не заменяется. При редкой ошибке публикации отчёта готовый проверенный ZIP может остаться без отчёта: выбрать новые имена для повторного запуска.

Шаблоны `.env.example` и публичные синтетические demo credentials остаются в исходной поставке. Рабочие `.env`, БД, пользовательские cookie, виртуальные окружения, модели и Python runtime не включаются. SHA-256 не является электронной подписью; сканер известных паттернов не доказывает отсутствие любых возможных секретов.

`PACKAGE-MANIFEST.json` и `OFFLINE-PREREQUISITES.txt` сохраняются неизменными из source ZIP и описывают его исходную часть. Для объединённого архива следует читать `OFFLINE-INSTALL-README.md` и полный `OFFLINE-PACKAGE-MANIFEST.json`.

## Границы доказательства

Проверена локальная CPython 3.12/macOS arm64 установка зависимостей с `--no-index`, без Python-сетевых соединений, и временный ASGI lifecycle smoke. Снимок содержит готовый интерфейс; Node/npm на целевой машине не требуется. Linux x86_64/Windows и машина без заранее установленного Python не проверены. Сам упаковщик не запускает приложение и не выполняет настоящий браузерный/микрофонный тест. Не переносите готовый venv на другой компьютер как замену офлайн-установки.
